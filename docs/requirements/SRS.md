## 2. 产品范围

OpenProtégé 面向个人和团队的本体工程与项目协作。目标产品包含桌面端与 Web 端：

- 桌面端：完整本地编辑本体。
- Web 端：项目管理和协作，支持公开/私有项目及角色权限。
- 首期跨端方式：显式文件交换；实时同步留待评估。
- 本体范围：OWL 2 为核心，优先验证 RDF/XML、Turtle 等常见格式。
- 托管：自托管优先。
- 首期 AI/Agent 方向：建议式建模、只读语义检索；写入需用户确认。

上述是产品目标与需求，不是当前实现事实。Apache-2.0 仅确认进入评估，不是已选许可证。

## 7. 数据、安全与审计要求

数据实体的目标概念可能包括用户、团队/工作区、项目、成员角色、本体文件/版本、导入作业、变更记录、AI 建议和审计事件；该列表是需求分析输入（PROPOSED），不是现存 schema。

已确认的首版权限矩阵如下；它不意味着实现已存在：

| 范围 | 角色 | 首版允许操作 |
|---|---|---|
| 团队 | Owner | 管理团队信息和团队成员；为团队项目分配成员前，目标用户必须已加入团队。 |
| 团队 | Admin | 管理团队成员；创建团队项目。 |
| 团队 | Member | 无团队管理权限；团队成员资格本身不授予团队项目访问权。 |
| 项目 | Owner/Admin | 管理项目元数据和项目成员。 |
| 项目 | Editor | 读取项目；本体编辑写入能力由后续本体模块实现。 |
| 项目 | Viewer | 只读。 |
| 公开项目 | 匿名 | 只读访问。 |
| 私有项目 | 非成员/匿名 | 拒绝读取和写入。 |

团队项目授权必须同时要求团队成员身份和显式项目成员资格。本体文件 API 的首个后端切片已实现；本体导入要求有效项目成员及 Owner/Admin/Editor 角色，版本查询和导出按项目访问权限执行。项目管理角色不能替代 API 对项目成员资格及具体操作授权的服务端检查。

至少仍需定义：

1. 认证失败、授权失败、对象不存在和输入无效的 API 错误契约。
2. 邀请有效期、撤销、管理员引导及账户恢复流程。
3. 文件大小、格式、解析深度/时间及错误恢复策略。
4. 外部 IRI 加载策略与网络隔离。
5. 变更记录、敏感信息日志规则和审计保留期。
6. 备份、恢复、迁移和自托管配置保护。
7. AI 建议来源、验证结果、确认者及变更审计字段。

上述细节尚未由产品决策完全定义，也未由实现验证。
