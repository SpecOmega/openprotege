## 用例边界

用例基于负责人确认的产品边界，并标明实现和验证边界。当前有 React Web 工作区和身份、团队、项目、本体文件 API；桌面端仍未实现。团队/项目角色见 [SRS](./SRS.md) 第 7 节。每项关联 [SRS](./SRS.md) 与 [验收标准](./acceptance-criteria.md)。

## UC-01 — 个人用户在桌面端本地编辑本体

- **参与者**：个人用户。
- **目标**：在不依赖实时 Web 同步的工作流中编辑本地 OWL 2 本体。
- **前置条件**：桌面编辑实现、支持格式和本地项目/文件模型已确定。（当前未满足）
- **主流程**：
  1. 用户在桌面端选择本地本体文件。
  2. 系统识别格式并解析；对受支持内容显示可理解的校验结果。
  3. 用户编辑本体内容并保存到明确的本地目标。
  4. 用户可导出文件并再次加载，以检查批准的语义保真规则。
- **失败/替代流程**：格式不支持、文件损坏或校验失败时，系统报告失败原因，不伪装为导入成功，也不覆盖用户文件。
- **关联需求**：OP-DESK-001、OP-ONT-001～006、OP-NFR-DATA-001。
- **验证状态**：未实现；需上游/技术 PoC 验证编辑、解析和保存行为。

## UC-02 — 团队管理 Web 项目

- **参与者**：团队 Owner/Admin/Member、项目 Owner/Admin/Editor/Viewer。
- **目标**：在自托管 Web 环境管理项目、可见性和成员角色。
- **前置条件**：服务已部署，用户通过邀请建立本地账号并登录。（代码已实现；完整角色矩阵/浏览器端到端仍待验收）
- **主流程**：
  1. 受邀用户设置本地密码并登录。
  2. Owner/Admin 创建团队并维护团队成员；Admin 也可创建团队项目。
  3. 项目 Owner/Admin 创建项目、设置可见性并显式配置项目成员。
  4. 对团队项目，系统同时验证成员当前属于团队且显式加入项目。
  5. 系统在服务端按项目与角色校验每次受保护请求；Editor 的本体写操作由后续模块提供。
- **失败/替代流程**：未认证、角色不足或跨项目请求时，服务端拒绝；不能仅隐藏界面操作。
- **关联需求**：OP-PRJ-001～003、OP-WEB-001～004、OP-NFR-SEC-001。
- **验证状态**：React UI 的登录、团队/项目列表和角色条件界面已实现；部分后端路径经 PostgreSQL API 集成测试验证。浏览器 E2E、Admin/Editor 完整权限矩阵及生产部署待验证。

## UC-07 — 管理员邀请用户并建立本地账户

- **参与者**：平台管理员、受邀用户。
- **目标**：在关闭自助注册的前提下，安全建立本地账号。
- **前置条件**：空数据库已由部署者显式引导首位平台管理员；管理员已通过本地会话认证。
- **主流程**：
  1. 管理员签发邀请，服务返回一次性 token；服务不发送邮件。
  2. 管理员通过部署方认可的安全渠道交付 token。
  3. 受邀人以 token 设置本地密码；服务存储 token 摘要和密码散列。
  4. 用户用本地凭证登录；受保护变更请求携带 CSRF token。
- **失败/替代流程**：非平台管理员不能签发邀请；错误、过期或已消费 token 被拒绝；空用户数据库没有显式 bootstrap 配置时服务拒绝启动。
- **关联需求**：OP-IAM-001～003、OP-NFR-SEC-001。
- **验证状态**：Testcontainers 验证邀请、过期/重放拒绝、非管理员拒绝、token 摘要、登录/CSRF/logout；bootstrap 缺配置拒绝由单元测试覆盖。邀请撤销、恢复与限速尚未实现。

## UC-03 — 团队成员通过文件交换导入桌面修改

- **参与者**：有权访问项目的团队成员。
- **目标**：将桌面端编辑后的本体文件显式导入 Web 项目。
- **前置条件**：本地修改已保存为支持格式；用户对目标 Web 项目有写权限。
- **主流程**：
  1. 用户选择目标项目并发起文件导入。
  2. 系统校验用户权限、文件限制、格式和内容。
  3. 系统显示导入/验证结果；成功后按经批准的变更记录策略保存项目版本。
  4. 系统允许有权成员查看项目中已保存的内容。
- **失败/替代流程**：权限失败、超限、损坏、格式不支持或基线冲突时，拒绝写入并显示明确错误；原项目状态保持可识别。
- **关联需求**：OP-XCHG-001～004、OP-ONT-002～006、OP-WEB-003～005。
- **验证状态**：未实现；文件协议、冲突策略和服务端保存方案待 PoC。

## UC-04 — 成员导出本体供本地编辑

- **参与者**：有权读取 Web 项目的团队成员。
- **目标**：将 Web 项目中的本体导出至本地桌面端继续编辑。
- **前置条件**：目标用户具备读取权限；本体有可导出表示。
- **主流程**：
  1. 用户请求导出项目中的本体。
  2. 服务端校验项目访问权限，生成明确格式的文件。
  3. 用户在桌面端打开导出文件进行本地编辑。
  4. 后续回传通过 UC-03 的显式导入流程完成。
- **失败/替代流程**：未授权访问被拒绝；不支持的内容/格式须明确提示。
- **关联需求**：OP-XCHG-001、OP-WEB-003、OP-ONT-002～005。
- **验证状态**：未实现；公开/私有匿名导出语义和格式保真待确认。

## UC-05 — AI 提供候选建模建议

- **参与者**：有权操作项目的用户，可选 AI 功能。
- **目标**：查看候选本体建模建议，而不让 AI 静默修改项目。
- **前置条件**：AI 能力可选启用；用户有对应项目权限；输入和模型服务的数据政策已批准。（当前未满足）
- **主流程**：
  1. 用户主动提交请求或选择允许的上下文。
  2. 系统返回建议，并将其与持久化本体修改区分显示。
  3. 系统对候选结构执行定义的校验，向用户显示来源/限制。
  4. 用户拒绝建议，或检查后显式确认采纳。
  5. 仅经授权且确认后，系统才提交更改并记录必要审计信息。
- **失败/替代流程**：服务不可用时，核心编辑流程仍可用；校验失败、越权或用户未确认时不写入。
- **关联需求**：OP-AI-001～004、OP-AGT-001、OP-NFR-AI-001。
- **验证状态**：默认关闭的 AI Chat UI 和 OpenAI-compatible 服务端代理已实现；目前只提供建议式对话，不读取项目本体、不执行写入。外部 provider 真实连接、数据政策/隐私评审、来源溯源、候选校验、确认采纳与完整安全测试未验证或未实现。

## UC-06 — 只读语义检索

- **参与者**：有权读取目标语料的用户。
- **目标**：按语义查找可访问项目中的本体信息，不修改本体。
- **前置条件**：检索能力和数据范围定义完成；用户具备读取权限。
- **主流程**：
  1. 用户提交查询。
  2. 系统只检索用户有权访问的内容。
  3. 系统返回只读结果及可追溯来源。
- **失败/替代流程**：无权访问的数据不出现在结果中；索引不可用时清楚报告，不能降级为越权访问。
- **关联需求**：OP-AI-003、OP-AI-004、OP-NFR-SEC-001。
- **验证状态**：未实现；索引、语义查询技术和权限过滤策略待技术验证。

## UC-08 — 启动推理并预览规则结果

- **参与者**：有权读取本体版本的项目成员。
- **目标**：启动可用推理机，检查本体一致性/分类結果，并可临时应用一条 SWRL 规则而不修改保存版本。
- **前置条件**：项目中已有本体版本；调用者具备该项目读取权限；版本在配置的推理资源限制内。
- **主流程**：
  1. 用户在版本行选择 HermiT 并启动推理，也可用 Ctrl+R/Cmd+R 启动当前/默认版本。
  2. 系统检查 OWL 2 DL Profile、一致性、不可满足命名类及可用解释。
  3. 用户可查询命名类推断层级，或查询命名个体的所有及额外推断类型。
  4. 用户切换到 Rules 面板，输入一条使用完整实体 IRI 的 Manchester 语法 SWRL 规则及目标个体。
  5. 系统在临时 ontology 上运行规则，显示该个体的命名类型集合；原不可变版本保持不变。
- **失败/替代流程**：不支持的推理机、OWL 2 DL Profile 不符、未知实体、解释公理数超限、单 worker 繁忙或运行超时均须显式报告；Pellet/FaCT++ 未集成时不得展示为可选推理机。
- **关联需求**：OP-ONT-009、OP-ONT-010、OP-NFR-SEC-001、OP-NFR-REL-001。
- **验证状态**：HermiT 服务层单元测试覆盖一致性冲突解释、层级/个体分类、SWRL 只读推理与不可用引擎；React production build 可验证 TS/JSX，但浏览器端交互、API 端到端权限、超时取消和真实并发压力仍未验收。

## UC-09 — 恢复历史本体版本

- **参与者**：项目 Owner/Admin/Editor。
- **目标**：恢复历史本体内容，同时保留全部现有版本和可追溯记录。
- **前置条件**：用户对项目拥有本体写权限；来源版本属于当前项目且不超过当前配置的文件大小上限。
- **主流程**：
  1. 用户在版本列表中选择历史版本并确认恢复。
  2. 系统复制来源文件内容、格式和解析元数据，创建新的不可变版本，不更改来源版本或其他历史记录。
  3. 系统记录恢复操作者、时间、新版本 ID 和来源版本 ID；Web 刷新版本列表。
- **失败/替代流程**：Viewer、匿名无写权限用户、跨项目/不存在版本或超出当前文件大小上限的请求被拒绝；失败不得生成部分版本。
- **关联需求**：OP-ONT-008、OP-ONT-007、OP-NFR-SEC-001。
- **验证状态**：PostgreSQL HTTP 集成测试验证 Owner 成功、Viewer 拒绝、新版本、原始文件内容保真和审计来源关联；跨项目、不存在版本、恢复大小边界及浏览器 E2E 尚待验收。
