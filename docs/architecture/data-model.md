# 身份、团队与项目数据模型（首版）

状态：SOURCE-OBSERVED schema 已实现；授权/API 核心路径由 Testcontainers 集成测试验证  
日期：2026-10-09  
范围：Web 身份、团队、项目元数据和成员授权；不包括本体文件/版本。

对应 schema 由 `server/src/main/resources/db/migration/V1__identity_teams_projects.sql` 创建。基础身份、团队、项目和成员关系经 PostgreSQL API 集成测试验证；并发、迁移升级、删除和生产运维语义仍待验证。

## 实体与关系

| 实体 | 关键字段 | 关系及约束 |
|---|---|---|
| `users` | UUID、规范化邮箱、密码散列、平台管理员标志、创建时间 | 邮箱唯一；禁止公开自助注册。 |
| `user_invitations` | UUID、规范化邮箱、token SHA-256、过期时间、接受时间、签发用户、创建时间 | 只存 token 摘要；token 单次消费；过期或已消费邀请不可接受。 |
| `teams` | UUID、名称、创建时间 | 一个 Owner 由团队成员关系表达。 |
| `team_memberships` | 团队 UUID、用户 UUID、`OWNER/ADMIN/MEMBER`、加入时间 | `(team_id,user_id)` 唯一；用户移出团队后不自动删除用户显式加入的项目关系，但团队项目访问仍要求当前团队成员。 |
| `projects` | UUID、名称、公开/私有、可空团队 UUID、创建时间、更新时间 | `team_id = null` 为个人项目；非空表示团队项目。 |
| `project_memberships` | 项目 UUID、用户 UUID、`OWNER/ADMIN/EDITOR/VIEWER`、加入时间 | `(project_id,user_id)` 唯一；团队项目成员必须同时是该团队成员。 |
| `audit_events` | UUID、可空 actor UUID、事件类型、目标类型/UUID、可空 subject 用户 UUID、时间 | 成员变更记录所涉及的目标用户；不写密码、会话 ID、邀请明文 token 或请求敏感内容。 |

外键使用删除限制/软删除策略须在实现审查后确定；本模块暂不提供删除账户、团队或项目的 API。

## 授权规则

1. 匿名用户只能读取公开项目。
2. 私有项目只允许显式项目成员读取；团队成员身份不替代项目成员关系。
3. 团队项目访问同时要求当前团队成员关系和显式项目成员关系。
4. 团队 Owner 可管理团队与成员；Admin 可管理成员并创建团队项目；Member 无团队管理权限。
5. 项目 Owner/Admin 可管理项目元数据和项目成员；Editor/Viewer 在本模块均只可读取元数据。Editor 的本体写能力仅由后续本体模块提供。
6. 项目 Owner 身份不得通过普通成员管理请求移除或降级；所有项目管理操作均由服务端检查角色。
7. 公开可见性只授予匿名读取，不授予写入。

## 初始管理员引导

空数据库首次启动由部署者显式设置首位管理员邮箱和密码；服务检测用户表为空后创建管理员，不使用默认口令或匿名初始化接口。已有用户时不重复创建。成功引导路径和密码散列已在 PostgreSQL 测试中验证；缺失配置失败路径、并发多副本引导及日志泄露检查尚未单独测试。配置值应由部署环境的 secret 管理机制提供，不写入版本控制或日志。

## 安全与事务约束

- 密码只以使用受支持密码散列函数生成的摘要存储。
- 邀请 token 使用密码学安全随机源生成；数据库仅保存单向摘要，接受动作原子检查有效期和未消费状态；当前代码采用 24 小时有效期，尚未作为产品策略由负责人确认。
- 创建团队、项目及 Owner 成员关系在一个事务内完成，避免产生无 Owner 对象。
- 项目成员加入团队项目前须原子验证团队成员资格。
- 业务授权基于被请求对象的数据库关系执行，不能只信任请求传入的用户/团队/项目 ID。
- 审计记录与对应管理操作同事务提交；不得记录凭证或邀请 token。
