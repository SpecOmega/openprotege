# 05 — 安全审计边界与风险

审计日期：2026-10-09

范围：OpenProtégé 当前工作树的 Web foundation 与首个身份/团队/项目 API；不是完整渗透测试，也不将未覆盖攻击面标记为已发现漏洞。

语言：中文主文档；英文翻译状态为 Pending，见 [索引](./README.md)。

## 结论

当前已有 Java/Spring Boot/PostgreSQL 服务和本地账户邀请、session/CSRF、团队/项目 API。Testcontainers 集成测试验证若干正反向授权路径、邀请单次使用、密码散列、登录/退出和 CSRF。测试不是全面安全审计；尚未验证登录限速、密码恢复、会话持久/多副本、完整角色组合、部署代理/TLS、邀请过期边界和生产威胁模型。没有在本次有限检查中确认可利用漏洞；覆盖范围外风险仍未判定。（VERIFIED / UNVERIFIED）

## 验证边界

本次仅运行隔离 Testcontainers API 集成测试；未进行渗透测试、恶意文件解析、线上数据访问或生产配置变更。依赖漏洞扫描未执行。测试通过仅覆盖报告中列出的身份/授权用例，不等同于安全审计通过。

## 后续安全验收门槛

在可运行系统形成后，至少针对适用面验证：项目级越权读写、文件大小与解析错误、外部 IRI/SSRF、XSS/敏感日志、备份恢复和依赖风险。每项记录测试环境、命令、退出码、日志与修复回归结果。（PROPOSED）
