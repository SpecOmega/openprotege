# 09 — 工程路线图

审计日期：2026-10-09

本路线图按任务要求分 P0–P3。条目是拟议顺序，不是承诺工期、人员预算或已批准架构。

语言：中文主文档；英文翻译状态为 Pending，见 [索引](./README.md)。

## P0 — 解除开发阻塞

**目标**：形成可追溯的产品/许可/技术输入，并证明候选上游可构建和满足核心边界。

- 输入：本轮审计、固定上游 SHA、负责人对产品方向的确认。
- 工作：确认 MVP 与双端边界、格式范围、身份/托管模式、许可证策略；对 Desktop/Web 上游分别构建与测试；完成依赖/许可盘点、安全威胁边界与 PoC。
- 输出：获批 SRS/验收、架构 ADR、固定环境 PoC 报告、第三方来源台账、剩余风险清单。
- 验收：每项结论带状态、证据、命令与退出码；无法完成项列明原因和重试条件；决策与需求可追踪。
- 前置：产品与许可证决策。

## P1 — 核心本体工程能力与可靠性

**目标**：经需求批准后实现可验证的本体项目生命周期最小切片。

- 范围候选：创建项目、导入、校验、保存/变更记录、按权限查看、导出。
- 覆盖格式保真、错误定位、文件大小/解析资源限制、拒绝未授权和失败恢复。
- 验收：端到端用例及恶意/损坏输入测试自动化；本体往返测试遵循经批准的语义不变量；结果与需求编号对应。
- 不预设解析器、数据库、性能阈值或分布式架构。

## P2 — 双端、协作、权限与社区

**目标**：按批准的桌面/Web 职责边界提供跨端项目协作。

- 候选：桌面文件/项目工作流、Web 身份与服务端对象授权、协作冲突/版本、成员/组织/工作区、发现/讨论/评审、备份与恢复。
- 验收：跨端交换、并发冲突、项目隔离、恢复演练、可访问性和国际化测试均有明确测试数据与结果。
- 依赖：P0 决策、P1 稳定领域模型和持久化边界。

## P3 — AI 建模、语义检索与受控 Agent

**目标**：在基础权限和审计稳定后增加可选、可替换的 AI 能力。

- 候选：自然语言生成候选结构、语义检索、来源追踪、结构校验、用户确认/撤销。
- Agent 限定：最小权限、工具白名单、沙箱/隔离、人工审批、完整审计；不得绕过服务端授权直写数据库或任意执行命令。
- 验收：默认受限；生成只产生建议；所有写入经过校验与授权；拒绝越权/注入工具请求有自动化测试。
- 依赖：安全模型、可审计的本体操作接口、用户审批和变更记录。

## 阶段门

阶段间不得仅凭文档文件存在宣告功能完成。每项必须通过需求—实现—测试追踪，记录当前状态及可复现证据。未批准的范围保持待决，不虚构日期或产能估计。
